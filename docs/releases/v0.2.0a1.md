# Arcxiom v0.2.0a1 - proposed Rust-Native Architecture Kernel

**Experimental alpha; not a completed architecture standard, validated security control, or CAD/drafting conformance claim.** This release remains unpublished until all gates in FOSS-594 are met, including independent review and protected main. No release date is committed.

## What changes

The Rust CLI named arcxiom compiles a single .arch.yaml architecture source independently of Python, validates a typed architecture graph and selected relationship domains/ranges, exports canonical 0.1-draft ArchIR with a verifiable SHA-256 digest, traverses dependencies and performs deterministic source-to-source semantic diffs with optional conservative guardrail checks. It also verifies existing JSON ArchIR. Python remains a reference implementation and offers the original generic schematic PDF adapter; Rust compilation is the authoritative path for this version.

ArchIR language version **stays 0.1-draft**. This is a deliberate compatibility decision: version 0.2.0a1 names the implementation release, not a changed interchange schema. The published emergency-response example and digest are frozen as conformance fixtures. Unsupported grammar, tags, floats, dangling links, unknown fields and invalid constraints are rejected rather than dropped. Some previously ignored source metadata (such as constraint description) is now an error: remove or explicitly migrate such metadata before compilation.

## Build and use

Requires Rust 1.89 (MSRV). From the repository root:

    cargo build --locked --release --manifest-path rust/arcxiom-ir/Cargo.toml

On Unix, the executable is rust/arcxiom-ir/target/release/arcxiom; on Windows, arcxiom.exe. Put the binary on your PATH.

    arcxiom validate examples/emergency-response.arch.yaml --json
    arcxiom export examples/emergency-response.arch.yaml -o architecture.json
    arcxiom verify architecture.json
    arcxiom query examples/emergency-response.arch.yaml --id role.dispatcher --depth 8 --direction outgoing --json
    arcxiom diff examples/emergency-response.arch.yaml examples/emergency-response.arch.yaml --check-guardrails --json

Exit codes: 0 valid/no change; 2 invalid input, unsafe output or guardrail concern; 3 valid diff with changes; 64 invalid arguments. Compiler diagnostics include stable code, severity, message and property path. Warnings do not imply evidence of enforcement.

## Compatibility

The canonical hash is calculated on the compact sorted JSON representation without the sha256 property; arrays of nodes, relationships and constraints have stable semantic ordering. Strings follow Python JSON ensure_ascii escaping, with lowercase Unicode escape hexadecimal and surrogate pairs. Only i64 negative / u64 nonnegative decimal integers are accepted. Floating point is not currently supported.

The Python reference implementation remains at 0.1.0a1 for comparison and PDF rendering. The Rust compiler does not call or require Python. This release does not change or claim the semantics of the PDF adapter. There is no auto-upgrade or silent fallback for an unsupported ArchIR language version.

For source grammar, limits and type checks, see spec/archyaml-v0.1-compat.md. The CLI cannot authenticate a baseline, prove a running system complies with a model, or enforce a policy against live requests.

## Release qualification evidence required

- Windows, Linux and macOS matrix test success, rustfmt and clippy warnings-as-errors.
- Complete Rust unit, integration, hostile-input, deterministic-property, performance and CLI smoke tests; Python/Rust export, query and diff parity against frozen fixtures.
- Installable per-platform binary archives, per-archive SHA-256 checksums and resolved dependency inventory.
- Independent code/security review, explicit security/threat-model acceptance, review of license and dependency vulnerabilities.
- Repository default branch protection with required checks, no bypass, approved maintainer controls and manual arcxiom-release environment reviewers.
- One-time maintainer workflow dispatch with the reviewed exact main SHA, followed by separate manual publication of the draft GitHub prerelease.

This is a **release draft**, not a statement that the gates have passed. GitHub Actions produces nonpublic release candidates on PRs. No tags or releases are created on PR pushes.

## Explicit exclusions

Dimensioned CAD, ISO/BS/NCS profiles, multi-file imports, .arch shorthand, MCP integrations, signed security baseline promotion, and runtime-observed zero-trust evidence remain out of scope. The schema and vocabularies are draft, bounded, and intentionally not a complete architecture ontology.

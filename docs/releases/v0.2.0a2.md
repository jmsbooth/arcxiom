# v0.2.0a2 — Trustworthy Kernel qualification scope

Proposed kernel release, tracked in [FOSS-595](https://linear.app/lattix/issue/FOSS-595). The starting point is the [merged v0.2.0a1 kernel](https://github.com/jmsbooth/arcxiom/pull/2) at `48c6085`. FOSS-594 owns the a1 publication decision. The existing a1 preparation workflow requires the current protected main commit and the a1 Cargo version. Resolve a1 publication or explicitly retire that candidate before merging the a2 version bump. This branch prepares CI candidates only.

The candidate uses Rust package version `0.2.0-alpha.2`. Both the single-file language and ArchIR keep the experimental `0.1-draft` edition. External mappings will carry their own edition and adapter version. The input budget stays at 1 MiB and 1,000 entities.

## Replay the shared corpus

From the repository root, install the Python test dependencies and build the Rust CLI. Append `.exe` to the binary path on Windows.

```sh
python -m pip install -e '.[dev]'
cargo build --locked --release --manifest-path rust/arcxiom-ir/Cargo.toml
python scripts/check_conformance.py --compiler rust/arcxiom-ir/target/release/arcxiom --python-reference --report conformance.json
```

The evaluator uses only CLI output, the shared JSON Schema and the versioned [case manifest](../../tests/conformance/0.1-draft/cases.json). Pass an alternative CLI implementing `validate FILE --json` and `export FILE` via `--compiler`. Each accepted case must match the frozen digest at validation, in the exported claim and under independent recomputation. Each rejected case must return exit 2 and the expected error code and, where specified, property path. A timeout, skipped executable or unexpected return code fails the run. Corpus coverage is restricted to the shared profile. For example, Rust applies additional relation domain/range rules.

## Migration from the a1 Rust producer

Rust at `48c6085` hashed a literal U+007F (DEL) in any JSON string or property name as a raw byte. The published Python profile escapes it as the six ASCII characters `\u007f`. The a2 kernel implements that existing rule. A literal backslash followed by `u007f` remains ordinary text. Models without DEL retain their previous canonical digest. The published emergency-response fixture remains `9349e821e97cc8999dc170b9e0f4815bad22dbd1d3a38db46f565a3159b52d9f`.

For an affected a1 export, preserve the old artifact, original YAML and producer revision. Verify with the original a1 binary, re-export to a **new** file using a2, and verify with a2. In an empty migration working directory, with the two binaries available under the following names, run:

```sh
arcxiom-a1 verify archived-a1.json
arcxiom-a2 export original.arch.yaml -o candidate-a2.json
arcxiom-a2 verify candidate-a2.json
python -c "import json,pathlib; load=lambda p: json.loads(pathlib.Path(p).read_bytes()); a=load('archived-a1.json'); b=load('candidate-a2.json'); old=a.pop('sha256'); new=b.pop('sha256'); same=json.dumps(a,sort_keys=True)==json.dumps(b,sort_keys=True); print(old, new, 'same graph:', same); raise SystemExit(0 if same else 1)"
```

Retain the old/new digest mapping and both producer versions with downstream references. An a1 claim with the nonconforming digest fails a2 verification with `AXIR19`. A graph difference requires separate review before updating a reference. Keep historical approvals tied to their original artifact. Rollback uses the archived a1 pair. The [scalar fixture](../../tests/conformance/0.1-draft/scalars.arch.yaml) exercises both a DEL and literal escape text and has a Rust regression test for both producers' claims.
